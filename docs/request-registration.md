# تصحيح تسجيل مستخدم تطبيق طلبات الصيانة

تاريخ التنفيذ: 2026-11-03.

طُبق الكود المرفق في النافذة التي يحددها نطاقه `Maintenance_request.user_requst_windows.Register_Windows`، وكانت ملفاتها فارغة. لم يُعدل المسار القديم `Settings/Register_Windows`، ولم يُضف مدخل جديد لإنشاء الحسابات.

## الملفات

- `D:/0العمل الجديد/Maintenance request/Maintenance request/user_requst_windows/Register_Windows.xaml`: تصميم التسجيل كاملًا في XAML، بألوان تطبيق الطلبات وRTL وWin11Light، وقوائم الإدارة والمبنى والأيقونات والتحقق داخل الخانات.
- الملف المجاور `Register_Windows.xaml.cs`: تحميل الخيارات، قراءة معرّف اللوحة الأم، التحقق، الحفظ، التنقل والإغلاق.
- `D:/0العمل الجديد/Maintenance request/Maintenance request/Registration/RegistrationStore.cs`: تحميل الخيارات وحفظ الحساب ومعاملة قاعدة البيانات.

## السلوك

نوع قائمة الإدارات الصحيح هو `T_Mangment_Request`، والقائمتان ObservableCollection مرتبطتان بالتصميم، وتحملان بعمليات EF Core غير متزامنة. حدث الزر `async void` يستدعي دالة حفظ قابلة للانتظار؛ يمنع الحفظ المتداخل من الزر أو Enter.

يجري التحقق عند الحفظ من الاسم وكلمتي المرور والإدارة والمبنى، مع تركيز أول خطأ ومسحه فور الكتابة أو الاختيار، حتى داخل قائمة مفتوحة. خلفية الخانة تميز وجود قيمة. رسائل التشغيل والنجاح عبر ThemedMessageBox دون تبديل الثيم.

الحفظ يحافظ على ربط الحساب بالجهاز وترميز كلمة المرور وطريقة فتح الرئيسية الموجودة في المرفق. يفحص التكرار بالاسم ومعرّف الجهاز داخل معاملة Serializable، ويعامل `%` و`_` أحرفًا عادية بدل رموز Like، ويعيد فحص وجود الإدارة والمبنى قبل الإدراج. لا يتغير المستخدم الحالي قبل نجاح الاعتماد، ولا يكرر الإدراج عند تعذر فتح الرئيسية بعد الحفظ.

حد عمود PassWord الحالي 12 خانة **بعد** الترميز؛ لذلك يجري التحقق من طول القيمة المرمزة قبل إرسالها للقاعدة. لا تعديل لمخطط القاعدة أو ترميز تسجيل الدخول الحالي.
